# Prefácio

Existe um jeito de aprender que não funciona muito bem,
mas que a maioria dos livros técnicos usa mesmo assim.

Você recebe o conceito primeiro. Depois o exemplo.
Depois a explicação de por que o conceito existe.
O problema é que, sem ter sentido a dor que o conceito resolve,
a explicação desliza. Você entende as palavras mas não ancora em nada.

Existe outro jeito.

Você encontra o problema primeiro. Tenta resolver sem a ferramenta certa.
Sente a fricção. Às vezes fica preso por alguns minutos.
Aí a solução aparece — e faz sentido de um jeito diferente,
porque você acabou de precisar dela.

Este livro tenta fazer a segunda coisa.

---

Cada capítulo começa com um código que funciona mas tem uma limitação.
Você roda, observa, e experimenta forçar essa limitação.
Só depois aparece o conceito que resolve — com o nome técnico,
a teoria por trás, e o código que substitui o que não funcionava.

Isso significa que alguns momentos deste livro vão ser
deliberadamente desconfortáveis. Você vai rodar um código
e ver algo que não esperava. Vai tentar uma abordagem
e perceber que ela quebra num caso específico.

Esses momentos são o aprendizado acontecendo.

Não existe atalho para entender um sistema de verdade.
A compreensão profunda sempre veio de quem ficou preso num problema,
tentou várias abordagens, e só então encontrou a solução certa.
O nosso loop vai levar algumas horas. Cada dificuldade no caminho
é parte do processo — não um obstáculo a contornar.

---

Sobre o nível assumido: você sabe Python básico.
Escreve funções, usa listas, entende um `for`.
Nunca trabalhou com APIs (Application Programming Interfaces —
interfaces que permitem que programas se comuniquem pela internet)
de modelos de linguagem, com código assíncrono, com servidores web,
ou com frontend.

Tudo isso vai aparecer — mas sempre motivado por uma dor concreta,
nunca como conceito solto no ar.

Sobre o ambiente: Windows com PowerShell.
Todos os comandos do livro são escritos para esse ambiente.

---

Uma última coisa antes de começar.

Os experimentos nos capítulos não são opcionais.
Não são exercícios de fixação que você pode pular se achar que entendeu.
São a parte central do aprendizado.

Se você lê o experimento sem rodar o código,
está lendo sobre nadar — não nadando.
A compreensão real acontece quando o terminal responde algo inesperado
e você precisa parar e pensar por que.

Com isso dito: vamos construir.
